# QA-портфолио: веб-платформа LINKA (проект «Яндекс Мастерской»)

Опыт работы в кросс-функциональной команде (разработчики, дизайнеры, аналитики, QA) над реальным продуктом для НКО.
---
## 📌 О проекте

**LINKA** — веб-платформа для дефектологов и педагогов, позволяющая создавать интерактивные наборы учебных заданий, систематизировать их в библиотеке и отправлять ученикам.

* **Формат работы:** стажировка / командная разработка в рамках «Яндекс Мастерской» (команда 12 человек).
* **Роль:** QA-инженер (Manual / API ) / QA Lead (лид команды тестирования).
* **Заказчик:** некоммерческая организация (НКО).
---
## 🛠 Стек и инструменты на проекте

* **Тестирование API и сеть:** Postman (коллекции, окружения, JS-ассерты `pm.test`), Swagger, Chrome DevTools (анализ запросов, кодов ответа, request/response body).
* **Тестовая документация и трекинг:** Google Sheets (чек-листы, тестовые сценарии), GitHub Issues, GitHub Projects (канбан-доска, работа с бэклогом и статусами задач).
* **Дизайн и требования:** Figma (сверка верстки и пользовательских сценариев с макетами), спецификации API.

---

## ✅ Мои задачи и вклад в проект

1. **Проектирование тестовой документации:**
   * Выступала в роли QA-лида в команде из 12 человек: выстраивала процесс тестирования, распределяла задачи между участниками и координировала работу с разработкой.
   * Самостоятельно проводила декомпозицию продукта, выделяла ключевые объекты тестирования и определяла объём и приоритеты проверок.
   * Проектировала и поддерживала в актуальном состоянии чек-листы на основе макетов в Figma и технической документации.
   * Применяла техники тест-дизайна (эквивалентное разделение, анализ граничных значений, тестирование состояний и переходов) для максимального покрытия критического функционала.
     
2. **Функциональное и исследовательское тестирование Web-приложения:**
   * Проверка ключевых пользовательских флоу: создание и редактирование наборов заданий, работа с библиотекой материалов, отправка заданий ученикам.
   * Кросс-браузерная проверка, контроль синхронизации состояния UI и ответов бэкенда.

3. **Тестирование REST API:**
   * Проверка эндпоинтов по Swagger: валидация входных параметров (проверка граничных значений и обязательных полей), контроль корректности HTTP-статус-кодов (`200`, `400`, `404`, `415` и др.) и текста ошибок в теле ответа.

4. **Управление дефектами и командное взаимодействие:**
   * Локализация багов с помощью Chrome DevTools, запись скринкастов воспроизведения.
   * Заведение и ведение баг-репортов в GitHub Issues, взаимодействие с разработчиками при разборе спорных кейсов и ретест исправленных задач.
